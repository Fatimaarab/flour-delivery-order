# سامانه صدور حواله تحویل آرد

سامانه مدیریت فروش، انبار و خروج بار — شرکت آرد طلای سفید ماهان.

---

## این سامانه چه می‌کند؟

از تعریف راننده تا صدور و چاپ حواله، هر مرحله در سامانه ثبت و کنترل می‌شود:

**تعریف راننده** ← **صدور حواله** (آخرین مرحله)

قوانین کلیدی که سامانه اجرا می‌کند:

- حواله بدون **راننده** (با کد ملی معتبر) ثبت و صادر نمی‌شود
- حواله پس از **صدور نهایی** قابل ویرایش نیست؛ فقط ابطال و صدور اصلاحیه
- صدور و ابطال حواله به موجودی انبار دست نمی‌زنند (موجودی در این سامانه نگه داشته نمی‌شود)
- هیچ داده مالی‌ای فیزیکی حذف نمی‌شود
- هر تغییر وضعیت با نام کاربر، زمان و IP ثبت می‌شود

## نصب روی کامپیوتر برای توسعه

### پیش‌نیاز

- **Node.js نسخه ۲۲ یا بالاتر** — از [nodejs.org](https://nodejs.org) دانلود کنید

### مراحل

```bash
# ۱. نصب پکیج‌ها
npm install

# ۲. ساخت فایل تنظیمات
copy .env.example .env      # ویندوز
cp .env.example .env        # مک و لینوکس

# ۲.۱ ⚠️ ساخت کلید امن — بدون این، سامانه اجرا نمی‌شود
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
# خروجی را کپی کنید و در فایل .env جلوی JWT_SECRET بگذارید

# ۳. ساخت دیتابیس
npm run db:migrate

# ۴. وارد کردن داده نمونه
npm run db:seed
```

سپس در **دو پنجره ترمینال جداگانه**:

```bash
npm run dev:server
```

```bash
npm run dev
```

سامانه روی <http://localhost:3000> باز می‌شود.

> برای استقرار روی **سرور کارخانه**، فایل [DEPLOY.md](DEPLOY.md) را ببینید.
> آنجا فقط یک فرایند اجرا می‌شود، نه دو تا.

## کاربران نمونه

رمز عبور همه: `ard@1404`

| نام کاربری | نقش | چه چیزی می‌بیند |
|---|---|---|
| `admin` | مدیر سیستم | همه بخش‌ها |
| `sales` | فروش | مشتریان، حواله‌ها |
| `finance` | مالی / صندوق | پرداخت، ابطال، مرجوعی |
| `warehouse` | انبار | مشاهده رانندگان و حواله‌ها |
| `viewer` | گزارش‌گیر | فقط خواندن |

> ⚠️ **پیش از استفاده واقعی، رمز همه این کاربران را عوض کنید** و کاربران
> نمونه‌ای که لازم ندارید را غیرفعال کنید.

## متغیرهای محیطی

فایل `.env` در ریشه پروژه:

| متغیر | توضیح | نمونه |
|---|---|---|
| `DATABASE_URL` | مسیر فایل دیتابیس | `file:./data/ard.db` |
| `JWT_SECRET` | کلید امضای نشست کاربران | یک رشته تصادفی بلند |
| `PORT` | پورت سرور | `4000` |
| `BACKUP_DIR` | پوشه بکاپ‌ها | `D:\ArdBackup` |
| `BACKUP_KEEP` | چند نسخه بکاپ نگه داشته شود | `30` |

> 🔴 **`JWT_SECRET` روی سرور حتماً باید یک مقدار تصادفی بلند باشد.**
> با همین کلید، نشست کاربران امضا می‌شود. اگر کسی این کلید را بداند،
> می‌تواند به جای کاربران دیگر وارد شود. طرز ساختنش در `DEPLOY.md` آمده.

## دستورهای موجود

| دستور | کار |
|---|---|
| `npm run dev` | فرانت‌اند در حالت توسعه |
| `npm run dev:server` | سرور در حالت توسعه |
| `npm run build` | ساخت خروجی نهایی فرانت‌اند |
| `npm start` | اجرای سامانه در حالت عملیاتی (یک فرایند) |
| `npm run setup` | آماده‌سازی کامل: مهاجرت + ساخت خروجی |
| `npm test` | اجرای همه تست‌های خودکار |
| `npm run lint` | بررسی صحت تایپ‌ها |

| `npm run db:seed` | وارد کردن داده نمونه |
| `npm run db:studio` | مشاهده مستقیم دیتابیس در مرورگر |
| `npm run backup` | گرفتن بکاپ از دیتابیس |
| `npm run restore -- <فایل>` | بازیابی از بکاپ |

## ساختار پروژه

```
├── prisma/schema.prisma    ساختار دیتابیس — تنها مرجع جدول‌ها و روابط
├── prisma/seed.ts          داده نمونه
├── shared/                 منطقی که هم سرور و هم مرورگر استفاده می‌کنند
│   ├── permissions.ts          جدول اختیارات نقش‌ها
│   ├── receiptStateMachine.ts  جدول قوانین چرخه وضعیت حواله
│   ├── receiptCalc.ts          محاسبه مبالغ حواله
│   ├── finance.ts              مانده حساب و سقف اعتبار
│   └── weighbridge.ts          محاسبه باسکول و مغایرت
├── server/                 سرور و API
│   ├── modules/                هر بخش کسب‌وکار یک پوشه
│   └── middleware/             احراز هویت، کنترل دسترسی، خطاها
├── src/                    رابط کاربری
└── scripts/                بکاپ و بازیابی
```

**دو فایل مهم‌تر از بقیه:**

- `shared/permissions.ts` — چه نقشی اجازه چه کاری دارد
- `shared/receiptStateMachine.ts` — از هر وضعیت، به کدام وضعیت‌ها می‌توان رفت

اگر قوانین کسب‌وکار عوض شد، معمولاً فقط همین دو فایل تغییر می‌کنند.
